# 坑位库（剪映 → 达芬奇）

按"踩坑频率"排序。每条都是实测过的，不是推测。**报错时先看这里，再怀疑片子。**

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 变速段画面和剪映对不上，同一时间码画面超前/滞后 | 导入端把 `<in>`/`start` **再乘一次倍速**：`in_effective = in_export × speed`，误差 = `srcStart × (speed−1)`。FCP7 的 `<fi>` 和 FCPXML 的 `<timeMap>` 都会中 | **已在写入器根治**（`w_fcpxml._start_attr()`：`start = 源入点 ÷ 倍速`，且 timeMap 终点写精确秒使斜率严格等于 `src_dur/dur`）。老时间线用 `tools/fix_inpoint.py --go` 重放修复 |
| 2 | 放置返回对象但 `GetStart()=None` | 音频轨同位置被**孤儿链接音频**占着（历史删视频没删音频） | 先按素材名清 A1–A9 的孤儿音频再放；**不需要重启** |
| 3 | `AddFusionComp` 只有第一次成功，之后全返回空 | 达芬奇进程级限制 | 每进程集中做一轮；或先 `CreateFusionClip` 再补 comp |
| 4 | `timeline.AppendToTimeline` 变成 None | 大批量删除/变速后对象方法丢失 | 改用 `mediaPool.AppendToTimeline(...)`，参数相同 |
| 5 | 变速丢失，片段按原速播 | 慢速时 timeMap 终点写成 `max(src,dur)`，斜率=1 | timeMap 终点必须写 `src_dur` |
| 6 | 文字字体回退、位置差几像素 | 中文字体家族名不被 Text+ 解析 | 用 TTF 的**英文家族名** + 明确 Style（本项目 `PangMenZhengDao` + `Regular`） |
| 7 | 同一段声音播两遍 | 视频素材 `hasAudio="1"` 且另有独立声轨 | 视频素材声明 `hasAudio="0"` |
| 8 | 素材池同名项帧数对不上（241 vs 254） | 有 `Type=复合` 的二次包装项 | 取素材项要按 `Type == "视频 + 音频"` 过滤（复合项没有 File Path） |
| 9 | AI 抠像链看起来建好了，画面整段被抠黑 | `BitmapMask` 的图像输入端口叫 **`Image`**，不是 `Input`。`SetInput("Input", tf)` **静默失败**，空 mask = 全黑 | `bm:SetInput("Image", tf)` + `bm:SetInput("Channel","Alpha")`；验收要 `comp.Export()` 后 grep 到 `Image = Input` |
| 10 | 转 Fusion 片段后 `GetSourceStartFrame()` 恒为 0 | Fusion Clip 包装后源入点不可读 | 审计工具跳过（按名字 `Fusion Clip`）；内容正确性只能像素比对 |
| 11 | `AddFusionComp`/`SaveProject` 偶发返回 None，过会儿又正常 | 批量写操作后 API 临时锁定，**约 60 秒冷却自愈** | 轮询 `SaveProject` 直到 True 再继续；确认锁死才重启 |
| 12 | 审计报"导出在 `[0-79]` 凭空补了层" | 剪映对**从第 0 帧开始**的段不写 `target_timerange.start` 键（不是数据缺失） | 缺键一律按 0 处理；`audit_export` / `audit_inpoint` 已修 |
| 13 | 自检报"素材时长不足"，画面却完全正常 | 用补偿后的 `start`（源入点÷倍速）直接加时间线 `duration`，跨坐标系；0.8x 被放大 1.25 倍 | `(start + duration) × 倍速` 换算回源时间轴再比，容差 1 帧 |
| 14 | 链接音频入点被报偏几千帧 | 草稿存**原名**（`35.mp4`），导出用**哈希名**（`520326aa….mp4`） | 名字配不上时，只要同位置这一摞里有入点吻合的视频段就认账 |
| 15 | `AppendToTimeline` 返回 ok，时间线什么都没多 | 素材是"视频+音频"，会连视频一起放；目标视频轨被占 → **整条静默回滚**，返回值照样 ok | 只放音频必须带 `{"mediaType": 2}`；放完必须回读"该轨在 recordFrame 有无新片段" |
| 16 | 音频套 `SetSpeed({Percentage:80})` 后时长没变 | 音频的百分比是**改源消耗、不改时间线长度**（视频是改长度） | 想要「N 帧 + 源 M 帧」：先按 N 帧 1x 放置，再套百分比，源区间自动收到 M |
| 17 | 完整镜头到时间线后**只剩主体浮在纯黑上**，或**只剩中间一个小方块** | 两种 `common_mask` 被混为一谈：「形状蒙版」（`enable_video_mask` 管，真裁画面）和「调节蒙版」（`enable_adjust_mask` 管，只限定调色作用区，**不裁画面**）。把调节蒙版当形状蒙版套到 `MediaIn.EffectMask` 上，画面就被裁掉 | `enable_adjust_mask` 字段存在（尤其 `False`）→ 该段的 mask 属于**调节**面板，不许当形状蒙版处理。实测 1516：矩形 0.28×0.5 套上去 → 全屏变中间小方块 |
| 17b | 想读「草稿里这个蒙版到底用没用」，找不到字段 | **剪映不记录这个状态**。同一工程里「确认在用」的 2261 与「确认没在用」的 642，`segment` 键集合完全相同（都缺 `enable_video_mask`），`common_mask` 材料字段相同，`adjust_mask` 也都有有效数据（642 是 101/105 帧）。新版旧版草稿都一样 | 放弃找布尔开关。用 `tools/mask_report.py` 出的三条间接证据（显式关闭 / 调节蒙版 / 无下层）判定；判不了的进清单人工核 |
| 18 | 蒙版/抠像套完，整段视频变黑 | 该段在时间线里**就是最底层**，蒙版让画面透明后，下面没有任何东西可露，只能露黑。一个镜头不可能只有角色浮在黑色上 | 套蒙版前先算层数：该段区间内是否存在**更低的视频轨**与之重叠；没有 → 拒绝，除非显式声明"就要纯黑底" `_is_bottom_only()` |
| 19 | 按「起始帧相同」去草稿里找蒙版开关，配错段 | 时间线轨号 ≠ 草稿轨号。实测 2333：时间线 `V2` 的钢笔蒙版来自草稿 `T1`（`evm=None` 开启），而同帧草稿 `T0` 是矩形（`evm=False` 关闭）—— 差点把对的删了 | 配对要用「起始帧 + 时长 + 素材名」三元组；只看一帧就下结论必然错 |
| 20 | 想删掉误建的 Fusion comp：旧版 `DeleteFusionCompByIndex` 是 `NoneType`；21.1 里 `DeleteFusionCompByName` **能调但恒返回 `False`** | 达芬奇 Python API **没有可用的删 comp 方法**。21.1 实测：`dir()` 里只有 `DeleteFusionCompByName`（无 `ByIndex`），`callable=True`，但对确实存在的 comp（`GetFusionCompByName` 能找回）试遍原名 / 无空格名 / 索引 `1` / 字符串 `"1"` / 附加 `True`/`False` 参数 / 先 `LoadFusionCompByName` / 切到 Fusion 页 —— 全部 `False`，`GetFusionCompCount()` 纹丝不动。Fusion 侧 `comp:Delete()` 也不存在（`getmetatable(comp)` 无该方法） | 删 comp 只能**删片段 + 重放**（见坑 21/24/25）。`nlebridge/shellfix.py` 封装了这套：`python cli.py fix-shell -i <草稿>` 预演、`--go` 执行 |
| 21 | 时间线上一堆 comp，打开只剩 `MediaIn1 → MediaOut1`，画面正常但都在 Fusion 路径上渲染 | **空壳 comp**：先建了 comp 再判断"该跳过"就会这样。`AddFusionComp` 一旦调用就删不掉（坑 20） | 判断必须在**建 comp 之前**。计划阶段就排除（现行 `build_plan` 已如此）；只有历史工程需要手清。识别法：导出 comp，无 `EffectMask` 且无 `TextPlus` = 空壳 |

| 24 | 删段重放清空壳后，段尾少 1 帧，出现 1 帧空洞 | `AppendToTimeline` 的 `endFrame` 是**排他值**：要 N 帧就传 `startFrame + N`，传 `+N-1` 只得到 N-1 帧 | 放置后立刻回读 `GetEnd()-GetStart()` 与目标比对，别等最后一并查 |

## 三条通用配方

### A. 放不上去（返回 ok 但没东西）
1. 先查同位置有没有孤儿音频（坑 2）
2. 再确认素材项是"视频 + 音频"不是"复合"（坑 8）
3. 只放音频带 `mediaType: 2`（坑 15）
4. 放完**必须回读**，返回值不可信

### B. 找不到某条音频该放哪条轨
不能按导出里的 `lane -N` 反推 —— 达芬奇导入时会重排音轨号。
做法：从草稿取**同一条音轨**上的其它片段，按「起点+终点」在时间线上找落点，**投票**取多数那条。

### C. 变速片段的正确时长/源区间组合
目标 `时间线 N 帧 + 源区间 M 帧`（M/N = 速度）：
- 视频：删段 → 1x 按真实入点放 → `SetSpeed`
- 音频：**先按 N 帧 1x 放** → 再 `SetSpeed`（坑 16）

## 反模式（别做）

- 别在交换文件里一次性表达变速，然后再"看看对不对"——先用 `audit_export.py` 在离线阶段判死
- 别删视频段不管链接音频
- 别用"删段重放"去补一条丢了的音频：会把同段上已经做好的交叉叠化/发光一起删掉
- 别看到审计报错就改时间线：坑 12/13/14 都是**工具错了，不是片子错了**

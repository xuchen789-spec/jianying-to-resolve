# NLE Bridge

把剪映草稿转成达芬奇时间线，并保证**忠实**：边界、速度、入点、音轨、淡变都与草稿一致，且每一步都能验证。

前提认知：这条链路上**绝大多数失败是静默的** —— API 返回 ok 但没生效、mask 端口写错不报错、变速差 4 秒但画面看起来正常。所以流程里设了硬门禁，不许跳。

## 铁律：草稿是唯一事实源

转换的目标是**复现剪映工程**，不是"修好"它。所以：

- 允许的动作只有两种：**照草稿写**，或**因为草稿字段/结果约束而明确跳过并汇报**。
- 禁止的动作是"补齐"：草稿里没有的一律不加 —— 不补黑头、不补空层、不凭感觉套蒙版、不发明转场、不加调色。
- **别把这一条和 `post` / `fades` / `masks` 搞混。** 草稿里**确实存在**的转场、淡变与蒙版，必须由这些命令忠实还原 —— 那是复现，不是"补"。禁止的是"草稿没写、但你觉得应该有"。
- 任何跳过都必须**能说出理由并打印出来**，不许静默省略 —— 静默省略会让用户以为转好了。
- 判据只能来自两处：① 草稿字段（如 `enable_video_mask is False`）；② 结果约束（如"最底层套蒙版必露黑"）。**不许来自"我觉得这里应该有"**。
- 当两条冲突（草稿像是要蒙版，但套上去必然出黑），**默认按结果约束跳过，把选择权交回用户**，并给出显式的强制开关（`--allow-bottom`）。

## 第 0 步：自检（不可跳过）

```bash
python scripts/preflight.py --draft "<草稿目录>" --resolve
```

不通过就停，把缺的那项讲清楚：
- 缺 `pycryptodome` → 剪映 11.x 草稿是加密的，读不出来
- 连不上达芬奇 → `首选项 > 系统 > 常规 > 外部脚本使用 = 本地`，**改完必须重启达芬奇**
- `root` 指错 → 改技能目录下 `config.json` 的 `root`

源码仓库路径从 `config.json` 的 `root` 读。**不要**把 `nlebridge/` 复制进技能目录：两边各存一份必然分叉。

## 五阶段

### ① 解析草稿
```bash
python scripts/nb.py inspect -i "<草稿目录>"
```
看三件事：帧率推断的对齐率、轨数、总长。
**草稿里的 `fps` 字段不可信**（有工程标称 30fps、实际文件 24fps），一律以素材池/ffprobe 为准。

### ② 出交换文件
```bash
python scripts/nb.py convert -i "<草稿目录>" -t resolve -o <临时输出目录>
```
先导到临时目录，别覆盖用户上一次的成品。

### ③ 离线审计 —— 硬门禁
```bash
python tools/audit_export.py --fcpxml <刚导出的.fcpxml> --draft "<草稿目录>"
```
**退出码必须是 0** 才允许导入。非 0 时按类别定位：
- `入点偏移` → 写入器的倍速补偿坏了（坑 1）
- `速度不符` → timeMap 斜率没写对
- `缺段 / 多余段` → 先怀疑工具口径（坑 12 / 14），再怀疑片子

输出里 `已解释: 草稿自身重复 N 项 / 默认剔除水印层 N 项` 是**正常**的，不是错误。

### ④ 导入达芬奇（人工，不自动化）
1. 同一工程里**先删掉同名旧时间线**（两条同名最容易看错）
2. `文件 → 导入 → 时间线`
3. `_media_relink/` 要跟输出目录一起留着

导入后**第一件事**：
```bash
python tools/audit_inpoint.py -i "<草稿目录>"
```
不要直接去看成片。这一步才告诉你有没有段被倍速吞了入点。

### ⑤ 还原转场、淡变与蒙版（在线写回）
```bash
python scripts/nb.py post -i "<草稿目录>" --audit    # ① 离线：只数数量，不用开达芬奇
python scripts/nb.py post -i "<草稿目录>"            # ② 在线预演：逐条对账，不写入
python scripts/nb.py post -i "<草稿目录>" --go       # ③ 写入并保存
```
`post` 按 **转场 → 淡变 → 蒙版** 依次执行，一条命令做完，不会漏。顺序有讲究：
转场先占位（淡变的画面渐显也是 `Cross Dissolve`，会读已有转场避让）；蒙版最后建 comp；
`--fix-shell` 必须最前（它删段重放，会丢掉已挂的转场与 comp）。

单独跑某几步用 `--only`，例如 `--only fades,masks`、`--only trans`。
历史工程要清空壳加 `--fix-shell`：

```bash
python scripts/nb.py fades -i "<草稿目录>" --audit   # 也可以单跑，参数同上
python scripts/nb.py masks -i "<草稿目录>" --allow-bottom
python <root>/tools/mask_report.py -i "<草稿目录>"   # 套蒙版前先看清单
python scripts/nb.py fix-shell -i "<草稿目录>"       # 清空壳 comp（先预演）
```
一律先预演再 `--go`。视频淡变只用交叉叠化（`SetFades` 对视频不持久化）。

转场走 21.1+ 的 `AddTransition`，不重导 fcpxml。映射：叠化→`Cross Dissolve`、
闪白→`Brightness Flash`、闪黑→`Inverse Flash`、推镜变焦→`BCC+交叉变焦溶解`、
放射→`BCC+光线溶解`、炫光→`BCC+镜头光晕溶解`；未识别的进人工清单，不猜。
入口段没有余量（`source.start=0`，含静帧）时自动退 `left`，否则 API 静默返回 `None`。

**这三样一直是"分开的在线命令"，不是 `convert` 漏做** —— `convert` 只产出离线文件，
不需要达芬奇；转场/淡变/蒙版必须对着已打开的时间线写。以前要手动连跑三条，漏一条
时间线上就少一样。现在一律用 `post`，别分三次手工敲。

`masks` 开跑会先打印计划与跳过统计：

```
plan: 2 shape masks, 1 text segments
skip: 69 段带蒙版但不处理(不建 comp, 不留空壳)
  该段是最底层, 套蒙版必露黑                36 段
  调节蒙版未启用 enable_adjust_mask=False   30 段
  草稿里蒙版已关闭 enable_video_mask=False   3 段
```

**被跳过的段不会创建 Fusion comp** —— 计划在扫描阶段就排除了它们，comp 只在"有事要做"时才 `AddFusionComp`。所以新转出的时间线不会有空壳 comp。

`mask_report` 会列出每个带蒙版的段：位置、素材、蒙版类型、两个开关、下方层、AI 有效帧、以及判定理由。**先看这张表再决定要不要跑 masks**，不要直接套。

## 六条硬门禁

1. 改过写入器 → 必须 `convert` 到临时目录 + `audit_export` 退出码 0，才允许导入
2. 导入前删同名旧时间线；导入后先 `audit_inpoint`，不是看成片
3. 删任何视频段必须同删链接音频（否则占位，后续放置静默失败）
4. `AddFusionComp` 返回 None → 轮询 `SaveProject` 约 60 秒，**不要重启**；注意保存要用 `pm.SaveProject()`，本机 `proj.SaveProject` 是 None 属性（坑 22）
5. `AppendToTimeline` 返回 ok **不算成功**，必须回读确认片段真的落上了
6. 没打开目标时间线时不许跑 `post` / `fades` / `masks`；先确认工程名与总帧数

## 套蒙版前的两条否决（2026-11-18 新增）

**先接受一个事实：剪映草稿没有记录「蒙版是否启用」的布尔值。** 同一个工程里，确认在用的段和确认没用的段，`segment` 字段结构完全一致（都缺 `enable_video_mask`），`common_mask` 材料字段也一致，`adjust_mask` 里都有有效数据。所以不要去找"正确字段"，只能用下面三类证据。

写 `masks` 之前先问两句话，任一为"是"就不许套：

1. **这段是不是最底层？** 蒙版让画面透明，下层没东西可露就只能露黑。一个镜头不会只有角色浮在纯黑上。判据：该段区间内有无更低的视频轨与之重叠（`_is_bottom_only()`，已内置）。这不是猜，是结果约束。
2. **这个 `common_mask` 是不是"调节蒙版"？** `enable_adjust_mask` 字段存在（尤其 `False`）说明它只限定**调色作用区**，不裁画面。当成形状蒙版套上去，全屏会变成中间一个小方块（实测 1516：矩形 0.28×0.5）。

配套：`enable_video_mask is False` 也是硬否定。

前两条是**草稿说的**（忠实），第三条是**结果约束**（必然黑）。默认三条全生效；如果草稿确实要"角色浮在纯黑上"，加 `--allow-bottom` 走忠实模式，底层也照套 —— 但这必须由用户明确要求，不许自己决定。

辅助信号（不单独用）：AI 抠像序列的有效帧占比。`6888` 只有 `34/164`（20%），基本等于没抠出来；`642` 是 `101/105`，说明数据有内容但不代表启用。看 `mask_report` 的 `AI有效` 列。

### 空壳 comp 的由来与善后

被跳过的段若之前已经建过 comp，会留下只有 `MediaIn1 → MediaOut1` 的**空壳**。新转换不会再产生，只有历史工程需要清。

**comp 在 API 里删不掉**（坑 20：21.1 的 `DeleteFusionCompByName` 能调但恒返回 `False`，`comp:Delete()` 不存在），只能用 `fix-shell` 走"删片段 → 按草稿重放 → 回填变换/变速"：

```bash
python scripts/nb.py fix-shell -i "<草稿目录>"        # 预演，看清要动哪几段
python scripts/nb.py fix-shell -i "<草稿目录>" --go   # 执行
```

它用草稿判空壳，三条件全中才动：草稿里有对得上的素材段、媒体池项 `File Path` 非空、不在蒙版计划里。文字层和 `NBMatteLoad` 合成因没有文件路径自动保留（坑 28）。有调色节点的段拒绝重建，要动得加 `--force`。

## 报错时先查哪里

**先看 `references/坑位库.md`，再怀疑片子。** 30 条实测坑（含 17b），其中 12 / 13 / 14 属于"工具错了、片子没错"。
命令与参数见 `references/命令手册.md`。

高频六条：
- 变速段错位 = 坑 1（导入端会把入点再乘一次倍速）
- 画面整段黑 = 坑 9（`BitmapMask` 的端口叫 `Image`，不是 `Input`）或坑 18（蒙版套在最底层）
- 中间一个小方块 = 坑 17（把调节蒙版当形状蒙版）
- "放上去了但没东西" = 坑 2 / 15（孤儿音频占位 / 少了 `mediaType: 1`）
- "画面变成下层的内容"、不黑也不报错 = 坑 27（片段被禁用，`GetClipEnabled()` 为 False）
- 想删 comp 却失败（旧版 `NoneType`、21.1 恒返回 `False`）= 坑 20，用 `fix-shell` 删段重放

## 交付时要讲清楚

- 时间线总帧数、视频段数、音频段数
- `audit_export` 与 `audit_inpoint` 的**实际输出**（多少项异常，不要写"应该没问题"）
- 哪些是人工补的、哪些效果无法自动还原（转换报告的待人工清单）
- 已知偏差逐条说明是**片子的问题**还是**工具口径**，不许含糊

## 改动与同步（唯一源 = 仓库）

技能目录 `~/.workbuddy/skills/nle-bridge` 是仓库 `skill/` 的副本，**不要直接改它**。

| 要改什么 | 改哪里 |
|---|---|
| 流程、门禁、坑位、命令手册 | 仓库 `skill/SKILL.md`、`skill/references/*.md` |
| 转换逻辑、审计、在线补齐 | 仓库 `nlebridge/`、`cli.py`、`tools/`（技能不复制代码） |

- 每次跑 `nb.py` 会先对齐一次：仓库里比技能目录新的文件自动复制过来（`NLE_SKILL_NO_SYNC=1` 可关）

- `preflight.py` 第 [5] 项会报偏离，红了就同步
- 反向情况（技能目录被手工改过、比仓库新）**不会**自动覆盖，只告警；要保留就先抄回仓库再提交
